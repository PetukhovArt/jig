"jig": minor
---

The comment gate (`jig/comments`) denies every time, not once: an edit that adds a comment or rewords one is refused on each retry. The gate applies the edit to the file on disk and compares the comments of the whole file before and after (the edit's old and new text when the old text is not in the file), so a comment moved unchanged, a removed comment and a comment that only lost part of its text pass, and cutting the tail of a comment is no longer denied once and then let through. It now lexes HTML, Svelte, CSS, SCSS, Less, Python, shell, Rust and Go besides JavaScript, TypeScript (JSX-aware), Vue (style blocks included) and C# (`#region` included); config files (a name that starts with `.` or holds `.config.` or `.conf.`) and a line-1 shebang are not checked. Tool directives count as comments (`/// <reference>`, `@vite-ignore`, `__PURE__`, `// <auto-generated>`, `eslint-enable`, `#pragma`); only a C# `#nullable` that is not a suppression passes. The denial no longer carries the `comments` atom. A project turns the gate off with `"rules": { "jig/comments": "off" }`; suppressions stay denied.
