A direct review is cheaper and fully counted. `jig review cost` reads the session's own transcript: its turns from a `jig-review` invocation to the next human prompt count as the `runner` of the merge request, so $ per 1000 lines and $ per thread compare with a review cycle's. A review whose plan has finders runs in one review-runner subagent instead of the session that asked for it (`jig review-plan` prints a `runner:` line), and the runner reads no state, posting doc or later step before forking its finders, so forks inherit only the review's context.
