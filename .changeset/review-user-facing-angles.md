`jig-review` hunts what the user meets, not the shape of code: angles 6 (reuse), 7 (simplification), 9 (fix altitude), 10 (conventions and smells), 11 (documents), 13 (architecture) and 17 (comments) are removed, and with them the default `conventions` finder, the `layer`, `spread`, `smell` classes, blocking findings and the optional simplifications of the FYI note. The project's checks own those rules; a project that still wants one reviewed adds its own angle of kind `conventions`. Angle 16 stays, on its own finder kind `tests` with role `test-reviewer` (standard tier, medium effort, `tiers.tests` in the project config): it reads the tests a partition adds or changes for a wrong one (it cannot fail when the behavior it names breaks, `Important`, class `false-guarantee`) and a redundant one (`Nit`), and reports them without deleting any; a `conventions` finder carries only the project's convention angles; `angles.16.enabled: false` turns angle 16 off. A removed angle number in `.jig/review.jsonc` is accepted and changes nothing; a removed selector token (`architecture`, `comments` and the rest) is an error. The rare gate no longer asks whether the fix adds code: a bug a tester using the feature as intended does not meet is a known risk, except data loss, security, a broken invariant and what the project's severity sections name. `jig review rules` no longer prints `architecture` lines.

Every spec deviation of a review goes into one thread, item by item, grouped as missing, done differently and unrequested: `jig review route` routes the lead as a `thread` (or a `discussion`) with the heaviest severity and every other spec finding as a `spec-item` of it; a later run adds its spec findings to the open thread by one reply, and the thread resolves when every item is closed.
