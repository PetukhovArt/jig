Breaking: jig judges nothing about UI files and names no design or app-control tool. The model records its judgement with `jig ui scope ui|none "<why>"`; the user's references are listed with `jig ui reference add "<source>" [--covers "<screen or state>"]` (or `none "<reason>"`), and jig-format files are attached with `jig ui reference attach <n> --image <png> --tree <json>` (`ui.reference.fetch` in `.jig/config.local.jsonc` may fetch them). `jig pre-mr` runs nothing for UI and checks receipts: `ui-scope` first; with scope `ui` also `ui-reference`, `ui-reference:<n>` per listed reference (written by `jig ui reference attach <n>`, with files or `--none "<why>"` for a text spec), `ui-reuse` (when `ui.components.map` is set), `ui-mockup` per reference with a tree and `ui-matrix`; with scope `none` nothing else. `jig skip-verify` waives only `ui-matrix`. Break-it is a recommendation line, no longer a requirement. A receipt counts until any file of the branch changes. The review UX angle runs unless `ui-scope` is `none` (or the project has no `ui` section).

`jig ui reuse` reads every changed file outside `ui.components.dirs`. `jig ui mockup <n>` reads the tree attached to reference n (`schema/ui-tree.schema.json`) and tokens from a W3C Design Tokens table with a `jig` extension for themes and the names code refers to a token by (`ui.tokens` files or `ui.tokens.command`, `schema/ui-tokens.schema.json`). `jig ui prove` runs the project's `ui.driver` command templates (`prepare`, `capture`, `reset`, in `.jig/config.local.jsonc`) per combination, or with `--collect` validates the results the agent captured into `.jig/ui/<branch>/<target>-<width>-<theme>[-<locale>]/` (`shot.png`, `audit.json`, `result.json`; `schema/ui-audit.schema.json`, `schema/ui-result.schema.json`), then records `ui-matrix`; it compares each reference image with the combinations it covers. `jig init` proposes a `ui` key from framework dependencies only. Skills describe an app control capability that never takes the user's focus: a check in the background, on another monitor or while the user works remotely runs without asking; one that would take the keyboard, mouse or window the user works in asks first in hitl, and afk leaves those checks to the end, records `jig skip-verify` and asks in the report whether to run them.
