# Comments

- Gate on (default): add or reword no comment, tool directives (`/// <reference>`, `@vite-ignore`, `__PURE__`, `#pragma`, `#region`) and doc comments included; the gate denies it on every call. Put the reason into a name, a type, the structure or the commit message. A comment that must exist (a license header, a directive) is added by a human: say in your reply which one and where. Removing text from an existing comment passes; config files are not checked.
- Gate off (`"jig/comments": "off"`) and in review, a comment is right only if it is: a license header; `TODO(<ticket>)` with a real ticket id; JSDoc or a C# XML doc (`/// <summary>`, `<param>`, `<returns>`, `<exception>`) of a public API that states what the signature cannot (units, ranges, side effects, errors); behavior forced by code you cannot change (library, platform, protocol, upstream bug) with the link to the issue or RFC; a tool directive that only looks like a comment (`/// <reference ...>`, `// @stratum-purity N`, `// <auto-generated>`, bundler magic comments).
- Everything else goes: restating the code, history (tickets, removed code, diffs), commented-out code, dividers, a doc comment that repeats the signature.
- An explanation of your own non-obvious code is a refactoring signal: rename, extract a named function, express it as a type, or reorder.
- A constraint in words ("do not delete", "keep in sync") becomes a type, a runtime check, a test or a lint rule.
- A comment holds only if the code next to it confirms what it says.
- Suppression directives (lint or type checker, `#pragma warning disable`) are a human's decision, gate on or off. Fix the finding instead.
- Agents copy what they see: one harmless comment spreads into every file that imitates it.
