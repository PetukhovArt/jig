# Questions

- **Fact**: one right answer sitting in the code, the docs or a command output. Look it up. Never ask it.
- **Observable fork** ("which approach works", "is it fast enough", "does the layout fit"): build the smallest prototype or experiment that would come out differently for each option. Run it, then decide.
- **Decision**: a product or taste call no experiment can settle. Ask it, once, with the options, your recommendation and the reason for it.
- Name the principle each option strengthens or weakens instead of calling one "cleaner".
- Never assume a shape of code you have not read: trace the producer and the consumer first, then recommend.
- A question whose answer depends on another open question waits until that one is answered.
- Never give the human a shorthand token to type back. Ask in plain words.
