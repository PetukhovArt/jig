# Commands

Run as `node "<plugin root>/bin/jig.mjs" <command>`.

| Command | What it does |
| --- | --- |
| `check edit <file>` / `check stop` | findings for one file / the end-of-turn gate against HEAD; `check stop` exits 3 with an `incomplete:` line when a check did not finish |
| `build [--atoms-only] [--check]` | validates atoms, role templates and flows; without `--atoms-only`, writes the tool plan to `.jig/cache/plan.json` |
| `atom <name>` | prints an atom |
| `init [--update] [--json]` | discovery by the catalog: found tools (a marker config kept out of git, as in `.git/info/exclude`, counts), what to ask the user, a proposed `.jig/config.jsonc` (with `--update`, the current config plus what it does not name); writes nothing |
| `slot new [--slug <s>] [--branch <b>]` | creates a slot worktree with offset ports and its own `agent-view.config.json`, seeded from the main checkout; with `worktree.depsPool`, its dependencies come from the dependency pool (`worktree deps`) |
| `slot show <N> <branch\|commit>` | checks the branch out detached in slot N (refuses on tracked changes) and runs the install command when a lock file changed, or with `worktree.depsPool` fills it from the dependency pool when the root lock file changed (with a gitignored lock file: any tracked `package.json`) |
| `slot ls [--json]` | slots and their ports |
| `slot rm <N> [--force]` | removes a slot's worktree; without `--force`, refuses on tracked changes |
| `worktree seed <dir>` | copies the main checkout's ignored files and recreates its ignored symlinks in another worktree, jig's `.jig/config.jsonc`, `.jig/config.local.jsonc` and `.jig/review.jsonc` included when `.jig/` is ignored in full; never overwrites tracked files |
| `worktree deps <dir>` | fills the `node_modules` of a worktree or the main checkout from the dependency pool in the repository's git common dir (`.git/jig/deps`): an entry for the root lock file and `package.json` (npm, yarn) is hardlink-copied in and `worktree.depsPool.after` runs; without one, another checkout of the repository with the same key and a fresh install becomes the entry and is copied in, else the install command (`slots.install`, else the lock file's own) runs and its `node_modules` folders become the entry. A gitignored lock file is not part of the key (every tracked `package.json` is): the key holds versions, one per lock file installed with it, a reuse takes the newest and writes its lock file into the checkout, a checkout with the same key and a newer lock file of its own becomes a new version first, and a miss runs the resolving command (`npm install`, `yarn install`) unless `slots.install` is set. Other lock files are skipped. Works without `worktree.depsPool`; exits 1 when the install, the copy or `after` fails ([dependency pool](../skills/jig-slots/references/app-slots.md)) |
| `worktree deps <dir> --save [--force]` | makes the `node_modules` the checkout has now the pool entry for its key, without an install: its files become hardlinks shared with the entry, so a saved main checkout is served from the pool. Keeps an existing entry as is; with a gitignored lock file, adds a version unless one holds the same lock file. Exits 1 when the root `node_modules` is missing or a link, or looks older than the lock file (its install stamp, `node_modules/.package-lock.json` or `.yarn-integrity`, is older), unless `--force` |
| `worktree deps --prune [--dry-run]` | from any dir of the repository: removes the pool entries, each version on its own, no checkout uses (no file of theirs has another hardlink) and the staging folders of dead runs, printing each and the count; `--dry-run` only prints. An entry whose files were copied instead of hardlinked is kept, since its use cannot be told |
| `worktree remove <dir>` | removes a linked worktree: unlinks its symlinks and junctions first (the targets stay), then `git worktree remove --force`; `slot rm` and `worktree sweep` remove the same way |
| `worktree sweep [--json] [--ask] [--yes <path\|slot>]...` | sorts every worktree but the main checkout into `hold-current`, `hold-locked`, `hold-wip`, `hold-open-mr`, `prunable`, `recent`, `safe` (`hold-open-mr` asks `gh` or `glab`, by `reviewCycle.forge` or the `origin` host); removes only those confirmed at the `--ask` prompt or named by `--yes`, never a `hold-current`, `hold-locked` or `hold-wip` one |
| `review-plan [<base>] [--selector full\|quick\|auto\|<tokens>] [--spec] [--mode review\|pre-mr] [--mr] [--no-state] [--rereview] [--state <path>] [--agent <id>] [--json] [-- <pathspec>...]` | the review layout for the diff against the base, or for the given paths only: counted lines, the diff command, the inline path or the finders, their models and the judge, and the step files that apply to the run. `--rereview` (a re-review's new range): under 600 counted lines one deep/medium finder carries every angle and there is no deepening; from 600 lines the full layout. `--state <path>` (a re-review; implies `--rereview`) plans on the files whose patch against the base changed since the review the state records, counted by the branch's own changed lines, and prints a `re-review scope:` line (`unchanged`, `patches` or `full (<reason>)`); `diff:` then runs from `last_reviewed_sha`. A file renamed since the review is compared with the reviewed patch of its old path, so only the lines that differ count; `patches` names each rename (`<old> → <new>`) and `diff:` lists the old path too, so git shows the move as a rename. With finders it writes the diff once under `.jig/runs/review/diff-<hash>/` (parts of at most 1500 lines, each file whole, split into `code-*`, `tests-*` and `docs-*`, and an `index.txt` of line ranges) and prints it as `diff files:`, so subagents read files instead of running the diff again; each finder's `diff:` line lists only its parts: code for every finder, tests for angle 16, documents for angles 11 and 15 (`testPaths` in `.jig/review.jsonc` adds test globs) |
| `review-cycle queue\|state-path\|import-state\|base-check\|spec\|reconcile\|unresolved\|standing\|head\|spec-hold\|withdraw\|verdict` | the deterministic half of the [review cycle](review-cycle.md): the filtered queue with the outcome of each skipped merge request, the state path of a merge request, importing the old skills' state, the adapter's base-check and spec, the tally check, the count of unresolved threads without Nit and Pre-existing ones, the count of Important findings still standing in open threads, the forge head against the reviewed sha (`head <mr> [--reviewed <sha>]`: `UNCHANGED <sha>`, or `MOVED <reviewed> <head> commits=N` and exit 1), the spec hold, withdrawing threads, the per-ref verdict; exit 3 when the forge or the adapter cannot answer |
| `review cost [<session>] [--project <dir>] [--record] [--json]` | estimated $ of a review session (Claude Code transcripts: the session's `subagents/`), per role and per merge request, with unit metrics: diff lines code/tests/docs, $ per 1000 diff lines, posted threads, $ per thread, cache hit ratio. Without `<session>`: the latest session of the project. An agent joins a merge request by `!<iid>` or `MR<iid>` in its spawn description, and a role by the description's first word; an agent spawned under a runner subagent joins that runner's run whatever its description. A fork copies its parent's history: those turns count once, for the parent. The session's own turns from a `jig-review` invocation to the next human prompt count as the `runner` of its merge request (from the arguments, else the one its subagents name); a `jig-review-cycle` orchestrator's turns count as `other`. `--record` appends one line per run to `~/.jig/review-cost.jsonl` (`JIG_COST_LOG` overrides), each runner once. Prices: [user config](configuration.md#user-config) |
| `review rules [<base>] [-- <pathspec>...]` | the review's input documents: `index <path>` for each rules index on the walk up from the changed files (`discover.rules` of `.jig/review.jsonc`), `standard <path>` for the standard documents, `architecture <path>` for the architecture documents |
| `review state <state file>` | a review state in a few lines: shas, runs, the non-zero tally, one line per finding (status, severity, angle, `file:line`, thread, id, summary), without the comment bodies |
| `review cost --report [--by project\|week]` | the recorded runs per project, or per project and ISO week: runs, re-reviews, $, $ per 1000 diff lines, $ per thread over first runs |
| `pre-mr [<base>] [-- <pathspec>...]` | exit 0 when the branch's UI changes (in the given paths only) are proven or skipped with a level, else lists what is missing and exits 1 ([UI proof](ui-proof.md)) |
| `pre-mr proof "<command>"` / `pre-mr bug-bash "<result>"` | runs a proof command and records it when it exits 0 / records the bug-bash result |
| `skip-verify --level unit-test\|type-check\|none --why "<reason>"` | lets `pre-mr` pass with that level until the next edit |
| `task-status log <phase> <decision> [--why <text>] [--evidence <text>] [--result <text>]` | appends a row to the decision journal `.jig/runs/<branch>/task-status.tsv` |
| `task-status open [--lang en\|ru] [--no-browser]` / `task-status path` | builds the HTML page from the journal, opens it in the default browser (not with `--no-browser` or `CI` set) and prints its path; the page takes answers to open questions and copies them for the chat / prints the journal path |
| `tiers [--agent <id>] [--json]` | the models of each tier for the agent |
| `loop [--days 7]` | aggregates the journal into improvement candidates |
| `doctor` | diagnostics: Node, config, each catalog tool, agent-view setup (in a project with markup or style files), deny block (in Claude Code or a plain terminal), journal size, locks |
| `version` | plugin version |

`hook <name>` is the entry point for `hooks/hooks.json`, not for people.
