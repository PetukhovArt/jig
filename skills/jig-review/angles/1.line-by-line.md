# 1 · Line by line

**Class:** bug. **Category:** `correctness`. **Atom:** `evidence`.

**What to read.** Every hunk of the diff, then the whole function around it. A bug in an untouched line of a touched function is in scope: the edit opened it again.

**The question for every line.** Which input, state, timing or platform makes it wrong?

**Look for:**
- an inverted condition;
- an off-by-one at a boundary;
- access on `null` / `undefined`;
- a missing `await`;
- zero taken for an empty value (falsy zero);
- a swallowed `catch`;
- a copied line with the wrong variable;
- unescaped metacharacters in a regex.

**Evidence:** the quoted line plus the input on which it gives a wrong result.
