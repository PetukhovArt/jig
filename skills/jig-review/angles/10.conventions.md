# 10 · Conventions and smells

**Class:** rules. **Category:** `conventions`. **Gate:** only `CONFIRMED` of the rule form ([gates](../gates/shape.md)). **Atom:** `smells`.

**The source of rules is the review document block** ([step 02](../steps/02-rules.md)). No block: question 1 is off, question 2 goes by the base vocabulary, and the summary says so.

Two questions for every hunk.

**1. A written rule is broken.** Naming, types, imports, literals are rules too when a project document writes them: the boundary is the tooling, not the topic. Evidence: the quoted rule plus the violating line.

**2. A smell from the vocabulary.** The vocabulary is a document of the block with named smells; none → atom `smells` as the base vocabulary. Every item is applied to every hunk. A smell is a code shape; it has no input. Evidence: the smell name, the hunk line, the second participant of the shape (the second copy, the foreign field, the signatures). Severity: by the scale of the project vocabulary, otherwise by the [taxonomy](../gates/severity.md#default-taxonomy) (a structural smell `Important`, the rest `Nit`).

**Not a finding:** a rule the repository's tooling enforces: a linter rule from its config, the formatter, the type checker, a Skip section. Check it with a search in the config. A written rule without effect on behavior (where a comment or helper lives, code order) and a duplicate smell without an invariant are not findings either ([shape gate](../gates/shape.md#shape-gate)).
