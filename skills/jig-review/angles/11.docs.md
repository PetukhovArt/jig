# 11 · Documents in the diff

**Class:** cleanup. **Category:** `simplification`. **Gate:** only `CONFIRMED`. **Atom:** `docs`.

**Trigger:** every new or changed `*.md` in the diff, except the changelog.

Two questions in a row. The first sifts out a document that should not exist; the second judges one that should.

## Question 1: the document will go stale

Is it an ADR, a glossary or a navigation pointer? If not, the document retells facts whose source of truth is the code, and it will diverge from it. The criterion and the existence test: atom `docs`.

**Evidence:** `file:line` of the code the document retells.

## Question 2: the document and the code disagree

The document **passed** the first question: it is an ADR or a glossary. The document itself is judged: its agreement with the diff's code and with neighbouring documents. The diff's code against the ADRs and glossary in force, including the ones this diff changes, is judged by [angle 13](13.architecture.md), sections C and D.

`review.glossary` and `review.adr` in the [config](../references/project-config.md) turn the check off by document type.

**Glossary:**
- a term was added or renamed, and the code calls the concept differently: quotes of both lines;
- a term is defined differently in two glossaries: quotes of both.

**ADR:**
- an ADR was added, and the ADR index was not updated;
- an ADR reverses an earlier decision, and the earlier ADR is not marked superseded.

**Format and threshold.** An added or changed ADR records one decision that was hard to reverse, its context, the options and why the others lost; a routine choice is not an ADR. A glossary term has one meaning across the code, the documents and the conversation. Evidence: the quoted rule plus the document line.

**Severity:** `Nit`.
