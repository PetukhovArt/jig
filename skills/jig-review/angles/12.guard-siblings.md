# 12 · Guard without siblings

**Class:** bug. **Category:** `correctness`. **Atoms:** `root-causes`, `change-impact`.

**Trigger:** a hunk **added** a guard, early return, validation or branch: it introduced a new invariant, not changed behavior.

**Procedure:**
1. State the invariant in one sentence **without naming the file**: "at runtime a bound property belongs to the value applier; a local commit must not write it".
2. Take the symbols from the guard's condition and search each across **the whole tree**, not the diff.
3. A sibling is a place where the same precondition holds and the guard is missing.

**Evidence:** both quotes: the guard line from the diff and the sibling line without it.

**Gate:** only `CONFIRMED`, with the named input on which the sibling breaks.
**Severity:** `Pre-existing`; `Important` when the failure is silent and costs data.

The search is limited to the symbols of the condition: two or three searches, not reading the tree. Zero siblings is a valid answer.
