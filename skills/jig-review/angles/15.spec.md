# 15 · Spec conformance

**Class:** spec. **Category:** `spec`. **Gate:** only `CONFIRMED`. **Atom:** `evidence`. Carried by the rules finder, only when a spec was found ([prepare](../steps/01-prepare.md#spec)).

The only angle that looks not at the code but at the **goal**: does the diff do what was asked, and only that.

**Finder input:** the diff plus the spec text: an issue, a PRD, a spec file ([sources](../steps/01-prepare.md#spec)).

**Three questions, each with a required section:**

1. **Missing:** a spec requirement the diff lacks or implements partly. Evidence: the quoted spec line plus the place where the implementation should be and is not (or the line where it stops).
2. **Unrequested:** behavior in the diff the spec did not ask for: a new option, an extra branch, a refactoring on the way. Evidence: the diff line plus "the spec does not mention this" with a quote of the nearest item in meaning.
3. **Done differently:** the requirement exists and is implemented, but the implementation contradicts its wording. Evidence: the spec quote plus the line that does otherwise.

**Severity:** missing and done differently are `Important`: the diff does not solve the task. Unrequested is `Nit`, except when it changes behavior outside the task's scope: then `Important`.

**Not a finding:**
- the spec is silent and the code decided something itself: not unrequested when it is needed to meet a requirement;
- a mismatch with the focus note: that is `correctness` through the usual angles, not spec;
- a mismatch with the merge request description: the author wrote it; that is documentation drift, not spec;
- the spec is outdated and the author said so in the merge request: a learning, not a finding.

**A learning from this angle drops the candidate** (like cleanup): "this scope was deliberately moved out" is a typical exception.

## spec_quote

Every candidate carries `spec_quote`: the spec sentence it rests on, copied character for character, without retelling or shortening; for unrequested, the nearest item. Before returning, the finder checks it against the latest text of the spec (issue comments, later sections of the file): a later text cancels or changes the sentence → the candidate is restated against it with its quote, or not returned. The field goes into state unedited ([schema](../references/state-schema.md)).
