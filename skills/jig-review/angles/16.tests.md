# 16 · Wrong and redundant tests

**Class:** tests. **Category:** `correctness` for a wrong test, `conventions` for a redundant one. **Gate:** only `CONFIRMED`. **Atom:** `tests`: the criterion.

**Trigger:** every test added or changed in the diff. Untouched tests are not judged.

**Candidate cap:** none; every wrong or redundant test is returned ([finders](../steps/04-finders.md#what-a-finder-returns)).

**The question, in two parts:**

- **Wrong:** the test names a behavior (its title, its `describe`, the case it sets up) and cannot fail when that behavior breaks: no assertion or a trivial one, the expected value computed by the code under test, a mock of the unit under test or a mock that implements the asserted behavior, a negative case that passes for an unrelated reason. It reports a guarantee that does not exist; the next reader trusts it. Ceiling `Important` ([severity](../gates/severity.md#gates)).
- **Redundant:** it fails when only internals change, repeats another test, or is not warranted at all. `Nit`.

**Not a candidate**, any one keeps the test:

- it names a risk category: a regression of a real bug (its name describes the bug), a contract between modules, an edge case with a high error cost, an integration with infrastructure, a state machine or invariant;
- it is the only guard of a public API, protocol, config, migration, storage, security or published-package contract;
- it pins a call order that is observable behavior;
- it is a source or string check that is the cheapest independent guard: it fails when a user-facing key, byte or path changes and survives a rename;
- slow or static is not a reason.

**Finder:** role `test-reviewer`, one per partition with changed tests, standard tier, medium effort ([finders](../steps/04-finders.md#partitions-and-kinds)). It reports; the author deletes.

**Output:** a thread, although it changes no behavior: a wrong or redundant test pollutes the context of later model runs ([shape gate](../gates/shape.md#shape-gate)).

**Evidence:** the test line plus what it asserts and which item of the criterion it fails; for a wrong test also the edit that breaks the named behavior while the test still passes.

**Thread:** one per file ([merge per file](../steps/06-rank.md#merge-per-file)).

**Off:** `angles.16.enabled: false` in the [project config](../references/project-config.md); then no finder reads the test files.
