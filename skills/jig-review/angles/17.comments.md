# 17 · Wrong and redundant comments

**Class:** cleanup, except a wrong comment. **Category:** `correctness` for a wrong comment, `simplification` otherwise. **Gate:** only `CONFIRMED`. **Atom:** `comments`: the criterion and its allowlist.

**Trigger:** every comment or doc comment added or changed in the diff, and every doc comment whose code the diff changes while the comment stays.

**Candidate cap:** none; every wrong or redundant comment is returned ([finders](../steps/04-finders.md#what-a-finder-returns)).

**The question, in two parts:**

- **Wrong:** the code contradicts what the comment states: a parameter, unit, range, return value, side effect, error, order or invariant the code does not have, or a description of a caller, a flow or a behavior that is not there. The next reader, human or model, takes it as truth about the code. Ceiling `Important` ([severity](../gates/severity.md#gates)).
- **Redundant:** it is not in the allowlist and the code does not contradict it: restating the code, history, a divider. `Nit`.

**Output:** a thread, although it changes no behavior: a wrong or redundant comment pollutes the context of later model runs ([shape gate](../gates/shape.md#shape-gate)).

**Evidence:** the comment line plus the allowlist item it fails; for a wrong comment the code line that contradicts it.

**Thread:** one per file ([merge per file](../steps/06-rank.md#merge-per-file)).
