# 18 · UX

**Class:** bug. **Category:** `ux`. **Gate:** only `CONFIRMED`: initiator, path and effect ([gates](../gates/bugs.md)). **Atom:** `ux`: the criterion, sections A to E, and its catalog of values and signatures.

**Trigger:** the diff changes UI files: markup and components (`.vue`, `.tsx`, `.jsx`, `.svelte`, `.html`, not tests) or styles (`.css`, `.scss`, `.less`). Only what the diff renders or styles is judged.

**The question:** does a user of this change meet a defect of atom `ux` with realistic data, in an environment the project supports?

**Evidence**, one of two forms:

1. **From the code.** The initiator: the source that makes the worst value realistic (a schema or column limit, "unbounded", user input, an API field, a translation, a list without pagination). The path: the diff line that renders the value, then every element up to the box owner, including the wrapper's own source when a wrapper owns the box (atom `ux`, section A). The effect: the signature the user sees and its harm level. For sections B to E: the diff line and the missing branch, format, handler or rule.
2. **From the running app.** An `agent-view` screenshot or `dom` read with the worst value fed through the data boundary (a fixture, a mock, a URL flag), never set by `eval`, at the real container width.

**Severity:** `Broken` is `Important`, class `broken` ([severity](../gates/severity.md)). `Ugly` is `Nit`. `Fragile` is `Nit`. Section E (motion) is `Nit` unless motion blocks input.

**Not a finding:**

- a guard the box owner already has: in a parent, in global CSS, in a project wrapper or a library component; the judge refutes with its `file:line`;
- an environment the project does not support (atom `ux`, scope);
- taste, or a mismatch with a design reference;
- a value no real user produces;
- a defect in code the diff does not touch.

**Off:** `angles.18.enabled: false` in the [project config](../references/project-config.md).
