# 8 · Efficiency

**Class:** cleanup. **Category:** `efficiency`. **Gate:** only `CONFIRMED`. **Atoms:** `effects`, `why-this-number`.

**Look for:**
- extra work on a hot path;
- a closure keeping a large scope alive: a leak;
- an expensive value recomputed on every call where one computation is enough;
- a deep reactive container written by a high-frequency stream: each write tracks nested objects and wakes every dependent; the container must be shallow and updated by replacing the whole value (atom `effects`). A rare stream is not a finding.

**Evidence:** the call site proving the frequency plus the line doing the work.

**Severity:** `Nit`, like all cleanup, except a leak: a `CONFIRMED` leak with the quoted holding place (a closure, a subscription without unsubscribe, a listener without remove) is `Important`. A `CONFIRMED` deep reactive container fed by a high-frequency stream is `Important` too. Its evidence quotes three things: the subscription, the write into the deep container, and the proof of the rate: a timer interval, a per-frame or per-tick source, a loop, or a source whose own contract or docs name its rate. A subscription alone does not prove the rate; without that proof there is no finding. A long-lived application with a leak or with constant recomputation has broken behavior, not a style issue.

**Output:** extra work off a proven hot path is a simplification: `status: "optional"`, an item of the FYI note, not a thread ([shape gate](../gates/shape.md#shape-gate)).
