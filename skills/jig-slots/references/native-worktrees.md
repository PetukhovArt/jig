# The agent's own worktrees

Parallel delegates inside one feature write in **native** worktrees (`isolation: worktree` on a subagent, EnterWorktree, `claude --worktree`, a dir inside `.claude/worktrees/`). `jig slot` does not manage these dirs. To see the code run, commit and `jig slot show <N> <branch>` in a slot (`app-slots.md`); do not start dev in the native worktree. When one must run an app anyway, three traps are specific to that layout:

- **`agent-view` can silently attach to slot 0.** The dir sits *inside* the repo, so on agent-view ≥ 0.11 config resolution walks up and finds the **main checkout's** `agent-view.config.json`. Without its own config the worktree then verifies against the main app and reports success: the most expensive failure here, because nothing errors. Write `agent-view.config.json` into the native worktree before the first `agent-view` call, with a port no other checkout is using.
- **Gitignored files are still missing.** A native worktree gets only tracked files, and the miss is silent (the build falls back to tracked env defaults → wrong backend, no error). Run `jig worktree seed <dir>` once after the worktree is created: it copies the ignored files and links of the main checkout, as `jig slot new` does. A hook on worktree creation can run it too.
- **`node_modules` resolves from the main checkout** (directory walk-up: the worktree has none of its own). Node itself is fine with that, but vite/vitest **strict `/@fs`** rejects modules outside the worktree root. Symptom: `Cannot find module '/@fs/<main-checkout>/node_modules/...'` on the first test/dev import. Fix: run the project's `install` inside the worktree (preferred; for npm and yarn `jig worktree deps <dir>` installs once and gives every later worktree with the same lock file a hardlink copy, see Install and build cache in `app-slots.md`), or allow the escape in the tool config (`server: { fs: { strict: false } }` for vite/vitest). Walk-up also skips `node_modules/.bin`, so a git hook calling a bare tool fails the commit (lint-staged → `'prettier' is not recognized`); without an install, commit with `export PATH="<main checkout>/node_modules/.bin:$PATH"`.

Ports for such a worktree still follow slot math (`parallel-no-app.md`) if any other slot may run concurrently; at minimum never reuse a port another checkout is LISTENing on: pick a free one and write it into the worktree's `agent-view.config.json`. The rest of running an app in it (identity, launch, teardown by port) is in `app-slots.md`.
